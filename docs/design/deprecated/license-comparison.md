# Arke 开源许可证对比分析

> 目标：选择最适合 Arke 项目定位的开源许可证

---

| 许可证 | 类型 | 代表项目 |
|--------|------|----------|
| Apache 2.0 | 宽松型 | TensorFlow, Kubernetes, Swift |
| MIT | 宽松型 | PyTorch, React, Node.js |
| BSD 3-Clause | 宽松型 | NumPy, Flask |

| LGPL 3.0 | 弱 Copyleft | Qt, FFmpeg |

## 详细对比

### Apache 2.0

```
可以：商用 ✅ 修改 ✅ 分发 ✅ 私有化 ✅ 专利授权 ✅
不可以：使用商标 ❌
必须：保留版权声明 / 标注修改 / 包含许可证副本
```

**优势：**
- ✅ 包含明确的**专利授权条款**——使用者自动获得贡献者的专利许可
- ✅ 企业友好：大公司可以放心使用和集成
- ✅ 贡献者协议清晰：自动授予专利权
- ✅ 硬件厂商（NVIDIA, AMD, Huawei）可以闭源集成
- ✅ AI 编译器领域的主流选择（TVM, MLIR, XLA 都用 Apache 2.0）

**劣势：**
- ❌ 无法阻止竞争者闭源分叉
- ❌ 修改后的版本不强制开源

**适合场景：** 希望最大化采用率，吸引企业和硬件厂商参与

### MIT

```
可以：商用 ✅ 修改 ✅ 分发 ✅ 私有化 ✅
必须：保留版权声明
```

**优势：**
- ✅ 最简洁，全文仅约 170 字
- ✅ 限制最少，任何人都可以做任何事
- ✅ 社区接受度最高
- ✅ 与几乎所有其他许可证兼容

**劣势：**
- ❌ **无专利授权条款**——如果 Arke 涉及专利，使用者没有自动获得专利许可
- ❌ 无贡献者专利保护（有人可以贡献代码后反过来起诉专利侵权）
- ❌ 对大型项目来说保护不够

**适合场景：** 小型工具库、不涉及专利的项目

### BSD 3-Clause

```
可以：商用 ✅ 修改 ✅ 分发 ✅ 私有化 ✅
必须：保留版权声明 / 不用项目名做背书
```

**优势：**
- ✅ 简洁，增加了"不得用项目名为衍生品背书"条款
- ✅ NumPy, SciPy 等科学计算项目常用

**劣势：**
- ❌ 同 MIT，无专利保护
- ❌ 在 AI 编译器领域不如 Apache 2.0 主流

**适合场景：** 学术/科学计算项目

### MPL 2.0（Mozilla Public License）

```
可以：商用 ✅ 修改 ✅ 分发 ✅ 私有化部分 ✅
必须：修改的 MPL 文件必须开源 / 保留版权
```

**优势：**
- ✅ 文件级别的 Copyleft——只要求修改过的原始文件开源
- ✅ 可以在闭源项目中使用，只需公开修改的源文件
- ✅ 平衡了开源保护和商业友好
- ✅ 包含专利授权条款

**劣势：**
- ❌ 比 Apache 2.0 复杂，企业法务评估成本高
- ❌ "文件级 Copyleft" 概念容易让人困惑
- ❌ 在 AI 编译器领域不常见

**适合场景：** 希望保护核心代码同时允许商业集成

### GPL 3.0

```
可以：商用 ✅ 修改 ✅ 分发 ✅
必须：衍生作品必须同样 GPL / 提供源码 / 保留版权
```

**优势：**
- ✅ 最强的开源保护，所有衍生作品必须开源
- ✅ 防止闭源分叉
- ✅ 强制社区贡献回馈

**劣势：**
- ❌ **硬件厂商几乎不可能采用**（闭源驱动/工具链会被 GPL 传染）
- ❌ 企业集成困难
- ❌ 与 Arke 的目标（被广泛采用、对接多硬件）直接矛盾
- ❌ NVIDIA, AMD, Huawei 的工具链不会集成 GPL 项目

**适合场景：** 理念驱动的纯社区项目

### BSL 1.1（Business Source License）

```
可以：查看 ✅ 非商业使用 ✅
限制：商业使用需许可 / N年后自动转为开源
```

**优势：**
- ✅ 防止云厂商免费搭便车
- ✅ 到期后自动转为 Apache 2.0 等开源许可

**劣势：**
- ❌ 不是传统意义的"开源"，OSI 不认可
- ❌ 社区贡献意愿低
- ❌ 不适合基础设施/编译器项目

**适合场景：** 商业化产品

## Arke 项目的特殊考虑

### 1. 需要硬件厂商参与
Arke 的后端需要对接 NVIDIA (CUDA)、AMD (ROCm)、Huawei (Ascend)。
→ **GPL 直接排除**，硬件厂商不会集成 GPL 项目。

### 2. 涉及编译器专利
算子优化、代码生成领域可能涉及专利。
→ **需要专利保护条款**，MIT/BSD 的专利保护不足。

### 3. 希望被广泛采用
作为新语言/IR，首要任务是被采用。
→ **限制越少越好**，GPL、BSL 都会阻碍采用。

### 4. AI 编译器领域惯例
- TVM: Apache 2.0
- MLIR/LLVM: Apache 2.0 with LLVM Exception
- XLA: Apache 2.0
- Triton: MIT
- PyTorch: BSD 3-Clause (历史原因，现在倾向 Apache 2.0)

→ **Apache 2.0 是该领域的事实标准。**

## 推荐

### 首选：Apache 2.0 ✅

**理由：**
1. 专利保护——Arke 如果涉及算子优化专利，Apache 2.0 自动授予使用者专利许可，防止专利钓鱼
2. 企业和硬件厂商友好——NVIDIA、Huawei 可以放心集成
3. AI 编译器领域标准——与 TVM、MLIR、XLA 保持一致
4. 贡献者保护——贡献者自动授予专利权，防止"贡献后起诉"
5. 足够宽松以最大化采用率

### 备选：Apache 2.0 + 未来商业许可（双许可）

如果未来需要商业化：
- 核心语言/IR 规范：Apache 2.0（保持开源）
- 商业优化引擎/高级 Cost Model：商业许可
- 类似 Qt (LGPL + Commercial) 或 Elasticsearch 模式
